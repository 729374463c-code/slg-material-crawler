# ADXray 采集与导出问题记录

## 当前默认流程：Playwright MCP

1. ADXray 网页检索、打开素材、读取视频与详情数据，默认使用已安装的 Playwright MCP。先检查 MCP 当前标签和登录状态；它与内置浏览器或 Chrome 的登录态不一定共享。需要登录或验证码时由用户在该会话完成。
2. 用一条已知广告完成端到端核验：打开精确 `#/Product/Plan/<广告ID>` 页面，读出产品、媒体、预估曝光、累计投放、投放周期、视频加载状态和精确详情页 URL。可用样本：`https://adxray.dataeye.com/index/home#/Product/Plan/1313556206`。
3. 2026-09-18 的单条测试已跑通：Playwright MCP 成功读取该广告，页面显示 Bilibili、预估曝光 560.0M、累计投放 15 天、投放周期 2026-09-04～2026-09-18，视频已加载、时长约 50 秒。此前同广告记录为 558.5M，文案也不同；动态指标与关联文案必须记录采集时间，不能当作固定值。
4. 以上只证明单条详情访问和读取可行，**尚未验证批量检索、去重、导出及长期稳定性**。首次批量任务先做小批核验；只有完整批次通过，才能称流程已跑通。
5. MCP 失败时记录失败环节，先按其工具说明排查一次；不要反复重试、无提示地改用其他浏览器或把旧数据充作实时结果。无法继续时报告已核实与未核实范围。

## 2026-09-18 的实际情况

- 内置浏览器点击多次耗时约 21 秒，页面读取约 21～43 秒；30 秒执行时限不足，多个操作合并也可能超过 60 秒。
- 超时导致执行环境重置，需要恢复连接和进度；并非已证明 ADX 页面、用户网络或登录状态故障。
- 批量调试数据通道出现单次超过 60 秒的超时，没有跑通接口批量采集。接近固定的等待时间可能与控制通道等待或重试有关，但未经证实。
- 点击参数使用错误；点击素材文案只打开提示，视频封面才是有效详情入口。
- 最终通过已登录的内置浏览器打开视频详情弹窗，读取可见字段和精确详情链接，使用下一条按钮减少操作次数。
- 导出时另建简化模板，未沿用用户已确认的双层分组彩色表头和黄色数据区，导致样式不一致。
- 表格工具 HYPERLINK 计算不兼容，后以普通 URL 值加原生 Excel 超链接修正。原生超链接采用 OOXML 补充，不改动数据。
- 已核实 10 条素材，未完整核查检索到的 309 组。一个候选未达门槛不能证明其余候选都不符合。

## 后续必须遵守

1. 开始前核对当前日期、产品身份、筛选门槛、数量和交付范围，不悄悄增加限制或缩小范围。
2. 每次先用 Playwright MCP 验证一个完整样本：详情能打开、字段可读取、视频可加载、精确链接可取得。不能把上次成功当作本次已验证。
3. 使用 Playwright MCP 的定位、快照和只读页面检查完成检索与核验，优先读取所需局部状态。仅当出现慢响应时拆分操作，避免将多个慢动作叠加到同一次执行；不要假定旧内置浏览器的耗时仍适用。
4. 首次超时先确认当前页面和动作是否已生效，避免重复点击；调整执行粒度。相同方式连续两次失败后，不继续盲目重试或无提示切换浏览器。
5. Playwright MCP 是 ADXray 网页任务的默认通道；批量步骤若未验证，不得称为已跑通。MCP 受阻时说明具体环节，并就替代通道与用户沟通。
6. 使用正确的公开操作接口；点击后以最新页面状态确认结果。素材检索页优先点击视频封面以打开详情，已在详情页时直接读取，不必重复跳转。
7. 每完成一批，将已核实的数据和进度保存为本地记录，不仅放在容易丢失的执行环境变量里；不得保存账号密码、令牌或会话凭证。
8. 汇报区分已核实、已排除、未检查。局部排序和单条不符合不能作为全库数量结论。额外采集耗时明显时说明进展，不擅自把部分清单宣称为完整成果。
9. Excel 默认沿用用户已确认的原模板：双层分组表头、既定板块配色、黄色数据区、既定列顺序和单位。单独交付 Excel 不代表重新设计模板。缺失分析不得编造。
10. ADX 导出使用广告精确详情页链接，不使用会过期或返回 403 的视频直链，不添加重复详情列。链接需可点击并保留可追溯来源。
11. 仅做必要验证：代表性数据、筛选条件、去重、表格排版和链接导出。避免重复测试不变内容；修复严重显示或公式错误后交付。
12. 网站仍按先本地预览、用户确认后上传的规则；每次修改做本地 Git 存档，不自动上传 GitHub 或部署。

外部连接故障无法保证绝不发生，但不能重复已知的操作组织、模板复用和结果范围判断错误。
