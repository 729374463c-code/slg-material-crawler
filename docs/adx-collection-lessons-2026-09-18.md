# ADXray 采集与导出问题记录

## 2026-09-18 的实际情况

- 内置浏览器点击多次耗时约 21 秒，页面读取约 21～43 秒；30 秒执行时限不足，多个操作合并也可能超过 60 秒。
- 超时导致执行环境重置，需要恢复连接和进度；并非已证明 ADX 页面、用户网络或登录状态故障。
- 批量调试数据通道出现单次超过 60 秒的超时，没有跑通接口批量采集。接近固定的等待时间可能与控制通道等待或重试有关，但未经证实。
- 点击参数使用错误；点击素材文案只打开提示，视频封面才是有效详情入口。
- 最终通过已登录的内置浏览器打开视频详情弹窗，读取可见字段和精确详情链接，使用下一条按钮减少操作次数。
- 导出时另建简化模板，未沿用用户已确认的双层分组彩色表头和黄色数据区，导致样式不一致。
- 表格工具 HYPERLINK 计算不兼容，后以普通 URL 值加原生 Excel 超链接修正。原生超链接采用 OOXML 补充，不改动数据。
- 已核实 10 条素材，未完整核查检索到的 309 组。一个候选未达门槛不能证明其余候选都不符合。

## 后续必须遵守

1. 开始前核对当前日期、产品身份、筛选门槛、数量和交付范围，不悄悄增加限制或缩小范围。
2. 先验证一个完整样本：详情能打开、字段可读取、精确链接可取得。流程复用必须确认当前采集通道可用，不能把上次成功当作本次已验证。
3. 依据实际耗时拆分操作；在出现约 21～43 秒响应时，避免在一次 60 秒执行中叠加多个慢操作，预留足够余量。尽量复用已取得的状态，避免重复整页读取。
4. 首次超时先确认当前页面和动作是否已生效，避免重复点击；调整执行粒度。相同方式连续两次失败后，不继续盲目重试或反复切换浏览器。
5. 优先使用用户已授权且验证可用的通道。批量通道失败后，及时说明并使用可行的详情读取方式；不得把人工逐条读取说成已复用接口批量流程。
6. 使用正确的公开操作接口；点击后以最新页面状态确认结果。优先点击视频封面，并复用详情弹窗下一条入口。
7. 每完成一批，将已核实的数据和进度保存为本地记录，不仅放在容易丢失的执行环境变量里；不得保存账号密码、令牌或会话凭证。
8. 汇报区分已核实、已排除、未检查。局部排序和单条不符合不能作为全库数量结论。额外采集耗时明显时说明进展，不擅自把部分清单宣称为完整成果。
9. Excel 默认沿用用户已确认的原模板：双层分组表头、既定板块配色、黄色数据区、既定列顺序和单位。单独交付 Excel 不代表重新设计模板。缺失分析不得编造。
10. ADX 导出使用广告精确详情页链接，不使用会过期或返回 403 的视频直链，不添加重复详情列。链接需可点击并保留可追溯来源。
11. 仅做必要验证：代表性数据、筛选条件、去重、表格排版和链接导出。避免重复测试不变内容；修复严重显示或公式错误后交付。
12. 网站仍按先本地预览、用户确认后上传的规则；每次修改做本地 Git 存档，不自动上传 GitHub 或部署。

外部连接故障无法保证绝不发生，但不能重复已知的操作组织、模板复用和结果范围判断错误。
