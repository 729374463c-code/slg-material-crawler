# 每周广大大 SLG Top 素材自动更新设计规格

## 1. 目标

为现有 SLG 海外吸量素材情报库增加一条每周自动更新链路，使网站能够在每周一上午自动获取广大大中表现靠前的 SLG/策略广告素材，并以“待审核素材”的方式更新到网站中。

该功能的目标不是自动生成最终复盘结论，而是减少人工找素材、下载视频和初步拆解的重复工作，让团队每周复盘时可以直接查看本周 Top 吸量素材草稿。

## 2. 已确认范围

- 数据来源：广大大。
- 品类范围：SLG / 策略方向广告素材。
- 地区范围：不限地区。
- 排序指标：展示估值。
- 抓取数量：每周 Top 5。
- 执行时间：暂定每周一上午，北京时间。
- 发布策略：自动采集、自动更新网站，但素材状态为“待审核”。
- 视频策略：网站内直接播放，同时提供原始视频链接和广大大详情页链接。
- 本地归档：下载的视频统一保存到系统下载文件夹，不放入项目代码目录。

## 3. 不在首版范围

- 不做完全无人值守的正式周报发布。
- 不自动把拆解结论标记为“已确认”。
- 不抓取全量 SLG 素材。
- 不按转化率、收入、ROAS 或商业价值排序。
- 不建设复杂后台、成员权限或审核流。
- 不保证绕过验证码、登录风控或平台访问限制。
- 不把本地 Downloads 视频路径作为公网播放地址。

## 4. 推荐方案

采用“自动采集 + 待审核发布”方案。

每周任务自动抓取展示估值最高的 5 条 SLG/策略素材，下载视频，生成结构化拆解草稿，并更新网站的“本周 Top 吸量素材”区域。所有自动生成素材默认进入“待审核”状态，复盘负责人后续再判断是否转为“已确认”或进入正式复盘结论。

这个方案比完全自动发布更稳，因为广大大的登录态、页面结构、视频链接和素材品类识别都存在不确定性；同时它比纯手动录入节省大量素材检索和初步整理时间。

## 5. 每周任务流程

```text
每周一上午触发任务
→ 打开广大大
→ 复用已登录态
→ 进入展示广告页面
→ 筛选游戏分类：策略 / SLG 相关
→ 地区保持不限
→ 时间范围选择最近一周或最近新增素材
→ 按展示估值从高到低排序
→ 读取候选素材卡片
→ 排除历史已抓素材和明显非 SLG 素材
→ 取 Top 5
→ 打开素材详情页
→ 提取视频链接、详情页链接和吸量字段
→ 下载视频到 Downloads
→ 抽帧并生成创意拆解草稿
→ 写入素材 JSON
→ 生成网站汇总数据
→ 构建并部署 Netlify
→ 输出本周任务报告
```

## 6. 数据去重规则

优先使用广大大详情页中的素材 ID 或详情页 URL 作为唯一标识。

如果详情页 ID 不稳定，则使用以下字段生成去重键：

```text
产品名 + 渠道 + 视频 URL + 首次发现日期
```

已抓取过的素材不重复新增，但可以更新展示估值、热度、人气值、投放天数和最近发现时间。

## 7. 素材数据结构

每条自动采集素材建议保存为独立 JSON，同时生成一个网站可读取的汇总文件。

核心字段包括：

- record_id
- record_name
- workflow_status：默认 `pending_review`
- collected_at
- collection_week
- rank_by_display_estimate
- product_info
- creative_info
- production_method
- performance_data
- video
- source
- automation_log

视频字段建议如下：

```json
{
  "video": {
    "playback_url": "https://example.com/video.webm",
    "source_video_url": "https://example.com/video.webm",
    "guangdada_detail_url": "https://guangdada.net/modules/creative/display-ads/detail?...",
    "local_archive_path": "C:/Users/chenzhiqi/Downloads/slg-ad-videos/...",
    "playback_status": "available"
  }
}
```

说明：

- `playback_url` 用于网站内播放器。
- `source_video_url` 用于“打开视频链接”按钮。
- `guangdada_detail_url` 用于回到广大大详情页核验。
- `local_archive_path` 只作为内部归档记录，不依赖它做公网播放。

## 8. 网站改造点

当前网站主要读取单条 Clash of Clans 静态样本。要支持每周自动更新，需要改造成读取多条素材的结构。

首版建议增加：

- `materials.generated.json`：自动任务生成的网站汇总数据。
- “本周 Top 吸量素材”模块：展示最新一周 Top 5。
- “待审核”状态标签。
- 素材列表支持多条真实素材。
- 素材详情支持播放器、原始视频链接和广大大详情页链接。
- 对比页支持从本周 Top 素材中选择 2-3 条横向比较。
- 缺失字段统一显示“未提供”或“待确认”。

不建议首版加入复杂后台编辑。人工复核可以先通过修改 JSON 或后续增加轻量编辑功能解决。

## 9. 视频播放策略

网站优先使用 `playback_url` 直接播放视频。

播放器需要支持失败状态：

```text
视频暂时无法播放
请尝试打开原始视频链接或查看广大大详情页
```

每条素材详情页提供两个链接：

- 打开视频链接
- 查看广大大详情

如果广大大原始视频链接不允许跨站播放，首版可以保留链接作为兜底；后续再考虑把视频上传到可公开访问的对象存储或 Netlify Large Media 类方案。

## 10. 自动拆解策略

自动任务可以基于下载视频做初步拆解，生成草稿字段：

- 前 3 秒钩子类型
- 第一画面
- 是否直接展示结果
- 核心卖点
- 辅助卖点
- 是否有角色
- 是否有口播
- 是否有实机
- 是否使用假玩法
- 画面风格
- 时长
- 剪辑节奏
- 落版方式
- 本地化形式
- 制作方式

所有自动判断默认是草稿，不作为最终结论。网站应显示“待审核”或“自动拆解草稿”。

## 11. 失败处理

每周任务必须记录失败原因，而不是静默失败。

常见失败类型：

- 广大大未登录。
- 出现验证码或风控。
- 页面结构变化，无法读取素材卡片。
- 无法按展示估值排序。
- 无法打开详情页。
- 未找到视频资源。
- 视频下载失败。
- 视频格式无法分析。
- Netlify 部署失败。

如果任务部分成功，应保留成功素材，并在报告中列出失败项。

## 12. 任务报告

每周任务完成后输出一份简短报告：

- 执行时间。
- 抓取条件。
- 成功新增素材数量。
- 更新旧素材数量。
- 跳过重复素材数量。
- 失败素材数量和原因。
- Netlify 发布链接。
- 需要人工复核的素材列表。

## 13. 验收标准

首版完成后需要满足：

1. 能在每周一上午触发任务。
2. 能从广大大按展示估值抓取不限地区的 SLG/策略 Top 5 素材。
3. 能去重历史素材。
4. 能下载视频到系统 Downloads 文件夹。
5. 能保存原始视频链接和广大大详情页链接。
6. 能生成统一素材 JSON。
7. 能更新网站素材列表。
8. 网站可以直接播放视频，播放失败时能打开备用链接。
9. 自动新增素材默认显示为“待审核”。
10. 能自动部署到 Netlify。
11. 任务失败时能输出清晰原因。

## 14. 后续扩展

首版稳定运行 2-3 周后，可以考虑：

- Top 5 扩展为 Top 10 或 Top 20。
- 增加国家/地区筛选。
- 增加平台筛选。
- 增加“已确认 / 已归档 / 已失效”轻量状态管理。
- 增加素材复盘备注编辑。
- 增加周报自动草稿。
- 增加视频云端归档，减少对原始 CDN 链接的依赖。
- 增加素材表现趋势追踪。
