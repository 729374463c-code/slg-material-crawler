## 1. 项目背景

当前团队在分析海外 SLG 吸量素材时，主要问题不是“缺少优秀广告”，而是缺少统一的记录颗粒度和比较方法：

- 不同分析人员使用的字段不一致；
- 有的分析过于零散，只能作为灵感参考；
- 有的分析过细，填写成本高，不适合快速积累大量素材；
- 素材内容和吸量表现没有形成稳定的横向对照；
- 视频文件下载、打包和部署成本较高，且容易受到格式、体积和链接失效影响。

因此，需要在现有 Demo 基础上建立一套清晰、可扩展、只服务 SLG 品类的素材情报展示框架。

网站的核心价值是：

> 将 SLG 海外吸量素材从“凭经验评价”转变为“基于统一标签与吸量表现进行验证”。

## 2. 已确认的核心原则

### 2.1 服务范围

- 只服务海外 SLG 游戏广告；
- 不扩展到休闲、角色扮演、射击等其他游戏品类；
- 图四的方法论作为所有 SLG 素材共用的底层拆解规则；
- 当前继续使用 4 条已有素材作为第一版样本；
- Top War 不进入素材库；
- 原始资料没有提供的内容必须显示“未提供”，不得推测或编造为确定事实。

当前 4 条样本为：

1. Clash of Clans；
2. Whiteout Survival；
3. Lords Glory；
4. Savage Survival: Jurassic Isle。

### 2.2 数据范围

本期只展示吸量侧信息，不展示：

- 转化率；
- ROAS；
- 付费率；
- 收入；
- 商业价值评分；
- 无法获得或口径不稳定的效果数据。

主要吸量指标为广大大的“展示估值”。热度、投放天数、排名等只作为辅助判断。

### 2.3 视频处理方式

素材收集流程保持原有模式：

```text
使用 Codex 内置浏览器打开广大大
→ 登录用户账号
→ 检索 SLG / 策略类广告
→ 地区不限
→ 以展示估值为主要排序依据
→ 收集 Top 表现素材
→ 获取素材信息、视频链接和广大大详情页链接
→ 根据在线素材完成拆解
→ 更新网站数据
```

本期明确要求：

- 不把素材视频下载到本地；
- 不把素材视频复制进项目；
- 不在网页中插入或嵌入视频播放器；
- 不将视频文件随 GitHub 或部署包上传；
- 每条素材保留“打开视频”链接；
- 每条素材保留“查看来源”链接，即广大大详情页；
- 两个链接均使用新标签页打开；
- 视频直链可能过期，因此来源页链接必须保留，作为核验与兜底入口。

### 2.4 更新与发布规则

任何网站改动必须遵循：

```text
本地修改
→ 本地运行测试和构建
→ 在内置浏览器中打开本地预览
→ 用户检查并明确同意
→ 才允许提交或推送 GitHub
→ 才允许更新 Netlify / Sites 等线上环境
```

未经用户确认，不得自动覆盖线上版本。

1. 一条完整广告由“开头钩子 + 若干内容单元 + 行动承接”组成；

4. 内容载体包括吸量包装（头）、核心玩法卖点、吸量包装（尾）；
5. 情绪节奏通过压力、落差、释放、满足等变化维持观看；
6. 本期只展示方法示意，不生成每条素材的真实情绪曲线。

## 7. 页面详细需求

### 7.1 总览页

目的：让使用者在 30 秒内理解素材库当前有什么，以及本周重点看什么。

页面内容：

- 网站定位说明；
- 当前素材总数；
- 已确认素材数；
- 待复核素材数；
- 最近更新时间；
- 当前数据来源：广大大；
- 本周展示估值最高的素材；
- 常见一级卖点标签；
- 常见二级卖点标签；
- “进入素材库”按钮；
- “查看分析方法”入口。

展示要求：

- 使用少量指标卡和简洁列表；
- 不加入来源不明的趋势图；
- 当前只有 4 条样本时，不展示容易产生误导的百分比分布；
- 缺失数据不参与排名或平均值计算。

### 7.2 素材库页

目的：快速查看、筛选和横向扫描所有素材。

#### 7.2.1 表格规则

- 一行代表一条素材；
- 默认按展示估值从高到低排序；
- 展示估值缺失的素材排在末尾；
- 点击整行进入素材详情；
- 行内链接按钮点击时不得触发行跳转；
- 支持桌面端横向查看；
- 窄屏时允许表格横向滚动，不强行压缩到无法阅读。

#### 7.2.2 主表固定字段

| 顺序 | 字段 | 展示规则 |
|---|---|---|
| 1 | 产品名称 | 显示游戏名称，必要时附公司简称 |
| 2 | 视频链接 | 显示“打开视频”按钮，不显示播放器 |
| 3 | 排名 | 按当前统计周期内的展示估值排序 |
| 4 | 广告平台 | 支持一个或多个标签 |
| 5 | 展示估值 | 保留原始单位，并支持数值排序 |
| 6 | 投放天数 | 显示整数天；缺失显示“未提供” |
| 7 | 投放时间 | 显示起止日期 |
| 8 | 投放地区 | 多地区以标签或“全球 / 多地区”摘要显示 |
| 9 | 卖点标签 | 显示一级标签和最重要的二级标签 |

热度作为辅助字段：桌面宽度充足时显示；宽度不足时放入详情页，不要求始终占用主表列。

#### 7.2.3 筛选与搜索

本期支持：

- 按产品名称搜索；
- 按广告平台筛选；
- 按投放地区筛选；
- 按卖点一级标签筛选；
- 按素材状态筛选：已确认、待复核；
- 清空筛选。

本期支持排序：

- 展示估值；
- 排名；
- 投放天数；
- 最近投放时间。

### 7.3 素材详情页

目的：在不堆积过多字段的前提下，查看一条素材的完整信息和核验入口。

#### 7.3.1 顶部摘要区

- 产品名称；
- 公司；
- 素材编号；
- 状态：已确认 / 待复核；
- “打开视频”按钮；
- “查看来源”按钮；
- 加入对比按钮。

#### 7.3.2 吸量与投放信息

- 排名；
- 展示估值；
- 热度；
- 投放天数；
- 投放起止时间；
- 广告平台；
- 投放地区；
- 数据来源；
- 数据采集时间；
- 统计周期。

#### 7.3.3 卖点信息

- 一级卖点标签；
- 二级卖点标签；
- 核心卖点一句话说明；
- 必要时显示辅助卖点列表，但不写成长篇文章。

#### 7.3.4 辅助分析折叠区

默认收起，可显示现有网站已经记录的内容：

- 前 3 秒钩子类型；
- 第一画面；
- 是否直接展示结果；
- 核心卖点；
- 辅助卖点；
- 是否有角色；
- 是否有口播；
- 是否有实机或实机感画面；
- 是否使用假玩法；
- 画面风格；
- 素材时长；
- 剪辑节奏；
- 落版方式；
- 本地化形式；
- 制作方式及其组成。

这些字段只作为次要参考，不得抢占详情页主视觉。

#### 7.3.5 脚本规律预留区

本期页面需要显示模块位置，但不生成内容。包括：

- 脚本总结：空状态；
- 结构与节奏：空状态；
- 情绪曲线：空状态。

统一提示文案：

> 该分析模块已预留，将在后续版本接入统一脚本拆解结果。

数据结构可以预留字段，但当前值必须为 `null` 或空数组，不得使用虚假示例冒充真实分析。

### 7.4 素材对比页

目的：比较 2—3 条素材的吸量表现和主要创意方向。

进入方式：

- 在素材库中勾选素材；
- 或在详情页点击“加入对比”；
- 至少选择 2 条，最多选择 3 条。

对比维度：

- 产品名称；
- 广告平台；
- 投放地区；
- 排名；
- 展示估值；
- 投放天数；
- 投放时间；
- 一级卖点标签；
- 二级卖点标签；
- 核心卖点；
- 前 3 秒钩子类型；
- 是否实机；
- 是否假玩法；
- 制作方式。

对比页不默认展示图二的全部细分阶段，避免再次变成过细分析表。

当选择数量不足时，显示明确空状态，不创建虚假对比结果。

### 7.5 分析方法页

目的：让团队理解网站使用的统一拆解逻辑。

页面使用易懂图示表达：

```text
完整视频 = 开头钩子 + 内容单元 1 + 内容单元 2 + …… + 行动承接
```

每个内容单元包含两层：

| 层级 | 解释 | 示例 |
|---|---|---|
| 结构目标 | 这一段想让观众产生什么反应 | 激发兴趣、满足体验欲、推动行动 |
| 内容载体 | 画面实际展示什么 | 吸量包装、核心玩法、结果或 CTA |

页面还需要展示一条概念性的情绪节奏示意：

- 压力 / 落差；
- 释放 / 满足；
- 开头钩子；
- 体验兑现；
- 情绪高潮；
- 行动承接。

必须标注“方法示意”，避免使用者误以为这是当前某条素材的真实测量数据。

## 8. 数据结构要求

建议将现有 `src/data/material.ts` 中混合的类型、数据和页面适配逻辑拆分，但不要求引入数据库。

推荐结构：

```text
src/

  types/

```

### 8.2 数据规范

- 文字文件统一使用 UTF-8；
- 中文不得出现乱码；
- 数值字段与展示文字分开保存，例如 `displayEstimate` 用于排序，`displayEstimateLabel` 用于展示；
- 日期使用 `YYYY-MM-DD`；
- 多个平台、多地区和多标签必须使用数组；
- 缺失值使用 `null` 或空数组；
- 页面统一将 `null` 渲染为“未提供”；
- 不得把缺失值保存为 `0`、`未知值`或虚构数据；
- 一条素材只保留一个稳定 `id`；
- 直链和来源页必须分开存储；
- 不再保存或展示本地视频路径。

## 9. 现有网站逐项更新说明

### 9.1 `src/data/material.ts`

现状问题：

- 类型定义、静态数据和筛选逻辑混在同一文件；
- 多处中文出现编码异常；
- 包含 `videoUrl`、`videoLink`、`localArchivePath` 等旧视频逻辑；
- 字段颗粒度偏向旧版详细拆解；

## 10. 数据采集与更新流程

本期不建设自动抓取后台，但开发和后续维护必须按以下标准执行：

1. 使用 Codex 内置浏览器打开广大大；
2. 使用用户账号登录；
3. 如果出现验证码或安全验证，暂停并由用户完成，不绕过风控；
4. 检索 SLG / 策略相关广告；
5. 地区设置为不限；
6. 按展示估值排序；
7. 只选 Top 表现且与 SLG 明确相关的素材；
8. 排除重复素材、无法核验的素材和与 SLG 无关的素材；
9. 收集视频链接、广大大详情页链接和结构化数据；
10. 根据在线素材生成拆解草稿；
11. 人工确认后标记为已确认；
12. 更新本地数据文件；
13. 本地预览并等待用户批准；
14. 批准后才允许发布。

未来可将此流程封装为每周一上午运行的任务，但不属于本期交付。

## 11. 异常与缺失处理

### 11.1 数据缺失

- 统一显示“未提供”；
- 不显示空白表格单元格；
- 不把缺失值计入排序、平均值或结论。

### 11.2 视频链接缺失

- 禁用“打开视频”按钮；
- 显示“视频链接未提供”；
- 如果来源页存在，仍允许“查看来源”。

### 11.3 来源页缺失

- 禁用“查看来源”按钮；
- 不用广大大搜索首页冒充素材详情页。

### 11.4 链接失效

- 数据结构预留链接状态和最后核验时间；
- 网站不需要自动检测所有外链；
- 人工发现失效后标记“链接待更新”；
- 不重新启用本地视频打包作为默认兜底。

### 11.5 中文编码

- 所有源码、JSON、Markdown 和配置使用 UTF-8；
- 测试中至少断言一个中文产品字段和一个中文标签可以正常渲染；
- 不以终端乱码为理由保留源码乱码。
