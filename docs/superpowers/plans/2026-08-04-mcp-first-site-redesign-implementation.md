# SLG 素材情报网站：MCP 优先改造实施计划

## 1. 目标

在现有 `slg-creative-intelligence-demo` 项目上完成下一版内部 Demo：

- 使用广大大 MCP 提供的结构化数据作为主要数据源；
- 保留现有 4 条素材并迁移到新的统一数据结构；
- 素材库改为直观表格；
- 网页不嵌入视频，只提供可验证的外部链接；
- 增加素材详情页和分析方法页；
- 为脚本总结、结构与节奏、情绪曲线预留位置；
- 所有新数据先待复核；
- 完成后只在本地展示，得到用户明确确认后再决定是否提交和部署。

### 1.1 2026-08-04 最终页面范围确认

参考“SLG 新版”表格，页面拆分为两类信息，不再把全部内容挤在同一张超宽表中：

1. 截图左侧的产品、链接、吸量表现、地区和卖点标签，单独建设“竞品吸量素材调研”模块；
2. 创意拆解和制作方式进入单条“素材详情”页面；
3. 截图右侧红框的“脚本总结、结构与节奏”只预留位置，当前不分析、不生成、不导出；
4. 情绪曲线继续作为后续预留内容，不进入当前竞品吸量素材调研；
5. 竞品吸量素材调研预留飞书导出边界，当前只提供 CSV，不实现飞书接口；
5. 两步分析模式保持不变：MCP 获取基础数据及标签草稿，视频直链解析补充创意拆解和制作方式；
6. 广大大数据获取不再使用内置浏览器；
7. 网页不嵌入视频，只显示外部视频或原始广告链接。

### 1.2 改造模式和保护项

改造模式：`Redesign · Preserve`。

必须保留：

- 当前森林绿、灰白底、细分隔线的数据产品视觉语言；
- IBM Plex Sans / Noto Sans SC 正文字体和 IBM Plex Mono 数据标签；
- 8px 间距体系、4px 以内圆角和约 140ms 状态反馈；
- 总览、素材、对比等已有核心访问路径；
- 当前 4 条真实素材和已有人工拆解；
- Hash Router 与静态部署能力；
- 缺失值不编造、待复核结果不冒充确认结论；
- 本地预览确认后才能推送和部署。

需要改进：

- 将卡片 / 主从式素材页改为可扫描的数据表；
- 将数据表与创意详情拆开，避免超宽表同时承载长文本；
- 增加筛选后导出；
- 移除网页视频播放器和本地媒体路径；
- 明确外链类型、分析来源、置信度和复核状态；
- 为脚本规律提供稳定但不误导的预留区域。

需要移除：

- 本地视频路径和网页内 `<video>`；
- 泛化广大大搜索页冒充单条详情页；
- 未经复核的脚本总结、结构节奏和情绪曲线；
- 与本期目标无关的后台、权限、数据库和商业价值指标。

最高风险：现有 `src/data/material.ts` 同时混合字符串数值、页面字段和本地视频路径。先迁移数据模型并建立兼容读取，再替换页面，避免一次性重写导致4条素材丢失。

本计划替代 `2026-07-29-slg-creative-demo-implementation.md` 中关于“本地复制视频、网页播放视频、固定 1 条素材加 4 个空位”的旧实施方式。

## 2. 目标架构

```text
广大大 MCP
  ├─ search_creatives：Top SLG 列表与核心吸量数据
  ├─ creative_detail：候选素材趋势和相关记录
  └─ dictionaries：分类、国家、平台和标签解释
          ↓
data/guangdada-mcp/raw/       原始周快照，不做 UI 直接读取
          ↓
scripts/normalize-materials   去重、字段映射、日期转换、缺失值处理
          ↓
analysis/video/               临时读取视频直链，输出带证据的拆解草稿
          ↓
src/data/materials.json       网站稳定读取的标准化数据
          ↓
React 页面
  ├─ 总览
  ├─ 竞品吸量素材调研
  ├─ 素材详情
  ├─ 素材对比
  └─ 分析方法
```

公开前端不直接连接 MCP。MCP 调用由 Codex 任务执行，身份凭证不进入 Git 仓库、构建产物或浏览器。

创意拆解采用两步模式：第一步由 MCP 返回 AI 标签并预填；第二步由分析任务读取 `video_url`，补齐第一画面、口播、真假玩法、剪辑节奏、落版、本地化和制作组成。公开网站既不执行 MCP 调用，也不执行媒体解析。

## 3. 固定查询口径

第一阶段固定使用：

```json
{
  "app_type": 1,
  "tag_ids": [3046],
  "ads_type": [2],
  "duplicate_removal": 1,
  "sort_field": "-impression",
  "page": 1,
  "page_size": 20,
  "include_ai_tags": true
}
```

- `3046` 为 `策略:4X SLG`。
- 不传 `geo`，表示不限投放国家。
- 第一阶段最多取 20 条候选，减少额度消耗。
- 当前网站仍可只展示用户确认的 4 条素材；新结果进入候选快照，不自动发布。

## 4. 实施阶段

### 阶段 A：建立 MCP 快照与数据合同

目标：先把“数据怎么进入项目”固定下来，再改页面。

新增：

```text
data/guangdada-mcp/
  raw/
  reviewed/
scripts/
  normalize-materials.mjs
  validate-media-links.mjs
  prepare-video-analysis.mjs
src/types/material.ts
src/data/materials.json
```

工作内容：

1. 保存一份小型 MCP 响应样本，删除凭证和无关诊断字段。
2. 定义 `GuangdadaIdentity`、`Material`、`ReviewStatus`。
3. 原始数值与展示文本分离。
4. Unix 秒转换为 `YYYY-MM-DD`。
5. 用 `resolved_labels` 解析国家、平台、语言和分类。
6. 视频直链、原始广告链接、广大大详情页链接分别保存。
7. AI 标签保存为 `mcpDraftTags`，不直接覆盖人工卖点结论。
8. 增加去重函数和缺失值规则。
9. 增加 `videoAnalysis`、字段来源、置信度、时间戳证据和复核状态。

验收：

- `materials.json` 能由快照稳定生成；
- 同一快照重复运行结果一致；
- 不包含 MCP 凭证；
- 缺失值为 `null` 或空数组；
- 中文无乱码；
- 不出现转化率、ROAS、收入字段。

### 阶段 B：建立视频直链解析流程

目标：补齐 MCP 不能稳定提供的创意拆解和制作方式字段。

执行流程：

```text
读取候选素材 video_url
→ HTTP 与内容类型检查
→ 媒体工具前置检查
→ 临时读取视频
→ 关键帧、场景帧、结尾帧与音轨分析
→ 生成结构化拆解草稿
→ 与 MCP AI 标签合并
→ 冲突项标记待复核
→ 清理临时媒体
```

解析字段：

- 前 3 秒钩子类型、文案和作用机制；
- 第一画面；
- 是否直接展示结果；
- 核心卖点和按出现顺序排列的辅助卖点；
- 是否有角色、口播、实机和假玩法；
- 画面风格；
- 时长和剪辑节奏；
- 落版方式；
- 本地化形式；
- 制作方式及组成；
- 可选的脚本段落和结构节奏草稿。

关键证据采样：

- 0、1、2、3 秒；
- 每次明显场景切换；
- 视频 25%、50%、75% 位置；
- 结尾 3 秒；
- 口播转写对应时间段。

实现约束：

- 当前运行环境没有预装 `ffmpeg`，开始实现前先完成媒体工具预检；
- 媒体解析能力放在独立任务环境，不加入前端运行依赖；
- 临时媒体不能进入 `public/`、`src/`、Git 或部署包；
- 解析结束后仅保留外部链接、文本结论和时间戳证据；
- `video_url` 缺失但 `originalAdUrl` 存在时标记 `manual_required`，不强行解析网页；
- 两个链接都缺失时直接拒绝进入候选池；
- 任何字段没有明确证据时保持空值。

验收：

- 用一条 MCP 返回的 MP4 视频直链跑通解析；
- 输出符合类型定义的 JSON；
- 每个关键判断带来源、置信度和时间戳；
- MCP 标签与视频判断冲突时显示待复核；
- 临时目录没有残留广告视频；
- 分析失败不会阻断网站读取旧数据。

### 阶段 C：迁移现有 4 条素材

目标：不丢失已有分析，同时移除旧的视频本地依赖。

修改：

### 阶段 D：素材库改为表格

目标：让使用者快速横向比较 Top 素材。

修改 `src/pages/MaterialsPage.tsx`，页面名称统一为“竞品吸量素材调研”。一行一条素材，只承载参考截图左侧字段：

| 列 | 数据来源 |
|---|---|
| 产品 | `product.name` |
| 素材链接 | 视频直链或原始广告链接 |
| 排名 | 当前快照按展示估值计算 |
| 广告平台 | `acquisition.platforms` |
| 展示估值 | `acquisition.displayEstimate` |
| 投放天数 | `acquisition.runDays` |
| 投放时间 | `firstSeen` 至 `lastSeen` |
| 投放地区 | `countries` |
| 卖点标签 | 人工确认标签，AI 标签加“待复核”标识 |

不进入本表的内容：

- 前3秒详细拆解；
- 第一画面长文本；
- 制作方式说明；
- 脚本总结；
- 结构与节奏；
- 情绪曲线。

这些内容分别进入素材详情或预留区，从而保证竞品吸量素材调研可以稳定筛选和导出。

交互：

- 默认按展示估值降序；
- 支持产品搜索、平台筛选、地区筛选、卖点筛选和状态筛选；
- 支持展示估值、投放天数、最近投放时间排序；
- 点击行进入详情；
- 外部链接在新标签页打开且不触发行跳转；
- `videoUrl` 为空时使用 `originalAdUrl`；
- 两个链接都为空时按钮禁用；
- 长地区列表显示前 3 个加“更多”，详情页展示完整列表。

导出：

- 页面右上角提供“导出当前结果”；
- 第一版导出 UTF-8 BOM CSV，Excel、WPS 和在线表格均可直接打开；
- 导出的行与当前筛选结果一致；
- 导出的排序与页面当前排序一致；
- 固定导出列：产品信息、视频素材链接、排名、广告平台、热度、投放天数、展示估值、投放时间、投放地区、卖点一级标签、卖点二级标签；
- 展示估值、热度、投放天数使用原始数值，避免导出后无法排序；
- 多地区和多标签使用中文顿号连接；
- 链接导出完整 URL；
- 文件名使用 `SLG素材数据_YYYY-MM-DD.csv`；
- 不导出脚本总结、结构与节奏、情绪曲线或其他空预留字段；
- 后续数据量扩大后再评估 XLSX，不在当前 Demo 引入复杂表格后端。

验收：

- 4 条素材显示为 4 行；
- 表格没有视频播放器；
- 数值排序正确；
- 缺失数据不显示为 0；
- 窄屏可横向滚动。
- 导出结果与筛选、排序后的页面一致；
- CSV 中文在 Excel / WPS 中正常显示；
- 导出内容只包含左侧数据字段。

## 5. 后续每周任务设计（暂时搁置）

本节仅保留为后续设想，不属于当前版本的制作范围；本阶段不实现、不配置任何自动任务。

本次网站改造完成并通过后，再建立每周一上午任务。任务流程：

```text
周一上午触发
→ 调用固定 4X SLG 查询
→ 获取 Top 20 候选
→ 本地二次去重
→ 检查视频或原始广告链接
→ 对新素材调用详情接口
→ 对有视频直链的素材执行临时视频解析
→ 合并 MCP 标签和视频证据
→ 生成待复核 JSON 与变更摘要
→ 启动本地预览或生成待审分支
→ 等待用户确认
→ 确认后才合并与部署
```

任务不得自动把未经复核的数据发布到公网。

建议任务输出：

- 新增候选数量；
- 去重数量；
- 链接缺失数量；
- 视频解析成功、失败和需人工处理数量；
- MCP 标签与视频证据冲突项；
- Top 素材及展示估值；
- 本周消耗数据量；
- 需要人工确认的问题；
- 本地预览地址或待审分支名。

## 6. 风险与处理

| 风险 | 处理 |
|---|---|
| 视频直链缺失或失效 | 使用原始广告链接，标记最后核验时间 |
| MCP 不返回广大大详情 URL | 不伪造；等待接口增加或人工补充已核验链接 |
| 同素材多国家重复 | `material_id` 二次去重并合并国家 |
| AI 标签误判 | 只作待复核草稿，不覆盖人工标签 |
| MCP 无法补齐创意拆解 | 读取视频直链，按时间戳生成第二阶段解析 |
| 当前环境没有媒体解析工具 | 任务启动前预检，并使用独立受控媒体运行环境 |
| 视频解析失败 | 标记 `manual_required`，保留基础数据但不生成结论 |
| 数据额度消耗 | 先列表后详情、保存周快照、避免重复请求 |
| 静态站不能直接刷新数据 | MCP 任务生成 JSON，确认后提交并触发部署 |
| 未复核数据污染公网 | `pending_review` 默认不进入正式发布列表 |
| API 区域被误当投放地区 | 只用 `countries`，不把响应 `region` 写入投放地区 |

## 7. 完成定义

本阶段只有同时满足以下条件才算完成：

1. MCP 数据合同和标准化流程落地；
2. 一条 MCP 视频直链完成第二阶段解析验证；
3. 4 条现有素材迁移完成；
4. 素材库成为一行一条的表格；
5. 详情页、对比页、方法页可用；
6. 网页不嵌入或托管视频；
7. 外链类型准确且有缺失兜底；
8. 创意拆解与制作方式显示来源和复核状态；
9. 情绪曲线模块只预留；
10. 自动测试和生产构建通过；
11. 已在本地浏览器向用户展示；
12. 用户确认前没有推送或部署。
